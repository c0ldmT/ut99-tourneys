# Decisions

Short decision records. Newest at the bottom.

| #   | Decision                                                                                                                  | Why                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | Monorepo with pnpm workspaces, scope `@tourney`                                                                           | One repo for website, bridge, mod; shared TS packages                                                                      |
| 2   | Node/TypeScript, SQLite (Drizzle + better-sqlite3), Angular                                                               | Agreed stack; prebuilt better-sqlite3 binaries exist for ARM64                                                             |
| 3   | **NestJS** for the API                                                                                                    | Chosen over Fastify for structure (modules, DI, guards) despite ~25–28 % more idle RAM measured on a minimal app (≈ 30 MB) |
| 4   | Bridge connects outbound to the website via WSS                                                                           | Works behind NAT, website can be remote, several agents possible later                                                     |
| 5   | Event-sourced tournament state, shared projection                                                                         | Website and bridge agree by construction; offline bridge; admin overrides win via optimistic concurrency                   |
| 6   | Bridge↔mod: flat JSON lines, ≤ 255 bytes, ASCII                                                                           | Tiny UnrealScript parser; safe with old TcpLink limits; limit to be re-checked on 469f                                     |
| 7   | Mod reconnects after each level change, bridge holds state                                                                | UnrealScript actors do not survive travel                                                                                  |
| 8   | Closed system: Discord login only, per-user join token for everyone incl. spectators                                      | Requirement                                                                                                                |
| 9   | Empty slots filled with bots (default: placed on bye seeds)                                                               | Requirement; keeps engine free of bye special cases                                                                        |
| 10  | Scheduler: critical path first + rest rule                                                                                | Keeps WB/LB in step; avoids back-to-back runs except the unavoidable final stretch                                         |
| 11  | Map vote: Borda over ≤ 3 ranked picks, +3 mutual bonus, −2 per recent play, −1 per player who played it, seeded tie-break | Rewards common ground, avoids repetition, reproducible                                                                     |
| 12  | Clients must run 469+                                                                                                     | Allows 469 features in HUD/UWindow code                                                                                    |
| 13  | Mod package name carries a version suffix (`UTTourney_v1`)                                                                | UT99 clients cache packages by name; incompatible changes need a new name                                                  |
| 14  | Anti-cheat: none of our own; stay compatible with what the server already runs                                            | Requirement                                                                                                                |
| 15  | Bot vs bot default "watch live", optional "simulate" (skill-weighted)                                                     | Requirement                                                                                                                |
| 16  | A tie at the time limit always goes to sudden death (UT overtime)                                                         | Simple and familiar; the earlier `suddenDeath` switch had no sensible "off"                                                |
| 17  | Soft pause instead of `Level.Pauser`                                                                                      | A paused level stops ticking actors, which would also stop the bridge connection                                           |
| 18  | Mod caches access list and match in its ini before every travel                                                           | Logins on the new level can arrive before the bridge connection is back                                                    |
| 19  | Bridge bundles workspace packages from source                                                                             | `dist/` runs standalone on the Pi; never picks up a stale package build                                                    |
| 20  | Bridge generates `Tourney.ini`/`TourneyUser.ini` as copies of the installation's ini files                                | Server keeps its own settings (password, mutators); the user's files are never modified                                    |
| 21  | No `ServerPackages` entry for the mod until it has client-side classes (HUD, M6)                                          | Clients do not need to download anything yet                                                                               |
| 22  | Reminder broadcast every 30 s while the tournament waits (check-in, vote, ready, disconnect, pause)                       | Players always know who or what blocks the tournament                                                                      |
