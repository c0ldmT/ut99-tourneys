# Decisions

Short decision records. Newest at the bottom.

| #   | Decision                                                                                                                                                                                                 | Why                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Monorepo with pnpm workspaces, scope `@tourney`                                                                                                                                                          | One repo for website, bridge, mod; shared TS packages                                                                                 |
| 2   | Node/TypeScript, SQLite (Drizzle + better-sqlite3), Angular                                                                                                                                              | Agreed stack; prebuilt better-sqlite3 binaries exist for ARM64                                                                        |
| 3   | **NestJS** for the API                                                                                                                                                                                   | Chosen over Fastify for structure (modules, DI, guards) despite ~25–28 % more idle RAM measured on a minimal app (≈ 30 MB)            |
| 4   | Bridge connects outbound to the website via WSS                                                                                                                                                          | Works behind NAT, website can be remote, several agents possible later                                                                |
| 5   | Event-sourced tournament state, shared projection                                                                                                                                                        | Website and bridge agree by construction; offline bridge; admin overrides win via optimistic concurrency                              |
| 6   | Bridge↔mod: flat JSON lines, ≤ 255 bytes, ASCII                                                                                                                                                          | Tiny UnrealScript parser; safe with old TcpLink limits; limit to be re-checked on 469f                                                |
| 7   | Mod reconnects after each level change, bridge holds state                                                                                                                                               | UnrealScript actors do not survive travel                                                                                             |
| 8   | Closed system: Discord login only, per-user join token for everyone incl. spectators                                                                                                                     | Requirement                                                                                                                           |
| 9   | Empty slots filled with bots (default: placed on bye seeds)                                                                                                                                              | Requirement; keeps engine free of bye special cases                                                                                   |
| 10  | Scheduler: critical path first + rest rule                                                                                                                                                               | Keeps WB/LB in step; avoids back-to-back runs except the unavoidable final stretch                                                    |
| 11  | Map vote: Borda over ≤ 3 ranked picks, +3 mutual bonus, −2 per recent play, −1 per player who played it, seeded tie-break                                                                                | Rewards common ground, avoids repetition, reproducible                                                                                |
| 12  | Clients must run 469+                                                                                                                                                                                    | Allows 469 features in HUD/UWindow code                                                                                               |
| 13  | Mod package name carries a version suffix (`UTTourney_v1`)                                                                                                                                               | UT99 clients cache packages by name; incompatible changes need a new name                                                             |
| 14  | Anti-cheat: none of our own; stay compatible with what the server already runs                                                                                                                           | Requirement                                                                                                                           |
| 15  | Bot vs bot default "watch live", optional "simulate" (skill-weighted)                                                                                                                                    | Requirement                                                                                                                           |
| 16  | A tie at the time limit always goes to sudden death (UT overtime)                                                                                                                                        | Simple and familiar; the earlier `suddenDeath` switch had no sensible "off"                                                           |
| 17  | Soft pause instead of `Level.Pauser`                                                                                                                                                                     | A paused level stops ticking actors, which would also stop the bridge connection                                                      |
| 18  | Mod caches access list and match in its ini before every travel                                                                                                                                          | Logins on the new level can arrive before the bridge connection is back                                                               |
| 19  | Bridge bundles workspace packages from source                                                                                                                                                            | `dist/` runs standalone on the Pi; never picks up a stale package build                                                               |
| 20  | Bridge generates `Tourney.ini`/`TourneyUser.ini` as copies of the installation's ini files                                                                                                               | Server keeps its own settings (password, mutators); the user's files are never modified                                               |
| 21  | ~~No `ServerPackages` entry until the HUD exists~~ – since M6 the mod is in `ServerPackages`                                                                                                             | Clients need the HUD, vote window and follow classes                                                                                  |
| 22  | Reminder broadcast every 30 s while the tournament waits (check-in, vote, ready, disconnect, pause)                                                                                                      | Players always know who or what blocks the tournament                                                                                 |
| 23  | Chat commands are read by an invisible server-side `MessagingSpectator`                                                                                                                                  | Spectators' `Say` bypasses message mutators, and during the map vote every player is a spectator                                      |
| 24  | Reconnect limit per match (`maxReconnects`, default 2); the next disconnect forfeits, the last return shows a warning                                                                                    | A player cannot stall a match indefinitely by dropping                                                                                |
| 25  | Spectator chat commands are matched by name from the broadcast `Name:text`                                                                                                                               | `Spectator.Say` sends no team message, only a broadcast; names come from the access list                                              |
| 26  | Scoreboard is closed by walking pawns through the `Dying` state when the vote or the final standings start                                                                                               | Only `Dying.EndState` clears `bShowScores` on the client, and no client function exists for it                                        |
| 27  | Server and bridge stop `postTournamentShutdownSec` (default 30) after the final                                                                                                                          | The installation is free again right after the tournament                                                                             |
| 28  | Server profiles live in `bridge.json`; the website only picks a profile id                                                                                                                               | The website must not be able to define what the bridge executes                                                                       |
| 29  | NestJS 12 with explicit `@Inject(...)` everywhere                                                                                                                                                        | Works with esbuild/tsup/vitest, which emit no decorator metadata                                                                      |
| 30  | better-sqlite3 v13 without build scripts                                                                                                                                                                 | v13 ships prebuilt binaries (linux x64/arm64, windows) in the package; no compiler needed on the Pi                                   |
| 31  | Angular 21 (not 22)                                                                                                                                                                                      | Angular 22 needs Node ≥ 22.22.3; 21 runs on the Node ≥ 22.12 the repo requires                                                        |
| 32  | Browsers get server-sent events, bridges a WebSocket                                                                                                                                                     | SSE is enough for one-way updates and survives proxies; the bridge needs request/answer both ways                                     |
| 33  | Whole website behind login, CSRF via custom header, sessions stored hashed                                                                                                                               | Closed system as agreed; no CSRF tokens to manage; a leaked database does not leak sessions                                           |
| 34  | Spectators get server access by clicking "watch" (max. 64 entries incl. players)                                                                                                                         | The mod's access list has 64 slots                                                                                                    |
| 35  | HUD as a per-player HUD mutator (`TourneyClient`) plus one replicated `TourneyGRI`; no own HUD class                                                                                                     | Works with any ChallengeHUD subclass (SmartSB etc.), no conflict with other HUD mods                                                  |
| 36  | UWindow objects keep no actor references                                                                                                                                                                 | A closed window drops out of the window list; a reference would keep the old level alive at the map change                            |
| 37  | Text fallbacks (progress messages) only for clients whose HUD did not register                                                                                                                           | No double display; clients without the package still work                                                                             |
| 38  | Before a public release with changed client classes the package gets a new name (`UTTourney_v2`)                                                                                                         | Clients cache packages by name and GUID; a renamed package avoids version mismatches                                                  |
| 39  | SmartStockBots as an optional rule (`smartStockBots`), loaded via `ServerActors` in the generated Tourney.ini; the mod refuses bot respawns while bots are held                                          | Its recommended setup; per tournament on/off without touching the user's ini; FastRespawn must not break the ready check or the pause |
| 40  | Team deathmatch (2on2, 3on3, 5on5) uses the same bracket engine; an entrant of kind `team` holds members, substitutes and fill bots                                                                      | One engine and one event log for all modes; Monster Hunt can follow the same way                                                      |
| 41  | Teams exist per tournament only; captains invite with a link, solo players are drawn into teams before seeding (short teams first)                                                                       | Agreed with the project owner: no team management beyond one tournament                                                               |
| 42  | At most 2 substitutes per team; line-up changes go into the log as `team.lineupSet` and apply between games                                                                                              | Captains can react during a best-of series; the bridge sees the change like any other event                                           |
| 43  | Team brackets hold 4, 8 or 16 teams; the bot pool needs at least 2 × team size different bots                                                                                                            | 32 teams of five are unrealistic; two full bot teams must be able to meet                                                             |
| 44  | The mod's access list orders players of the current match first                                                                                                                                          | 16 teams × 7 players exceed the 64 entries; the match players must always fit                                                         |
| 45  | `TournamentTDM` extends `TournamentDM` and takes the team rules over from `TeamGamePlus` (scores, friendly fire, skins, end of game, bot attitude)                                                       | One code base for 1v1 and teams; `TeamGamePlus` cannot be a base class without duplicating the tournament logic                       |
| 46  | The line-up is fixed before the travel; bench players join as spectators                                                                                                                                 | A UT connection cannot switch between player and spectator without reconnecting                                                       |
| 47  | Team games do not pause on a disconnect: a stand-in bot after 20 s, replaced again when the player is back; too many disconnects = out of the match                                                      | Ten players should not wait for one; the team is not punished with a forfeit                                                          |
| 48  | Captains may start with bots after 60 s of ready check; at the timeout a team with anybody on the server plays, a team with nobody forfeits                                                              | Keeps the tournament moving without forfeiting teams over a single missing player                                                     |
| 49  | Website line-up changes are passive events: the bridge appends on top of them instead of re-planning                                                                                                     | A captain's change during a game must not restart that game                                                                           |
| 50  | Monster Hunt is a time race: both teams run the same map one after the other, the lower time wins                                                                                                        | Monster Hunt is co-op; a race compares the teams fairly on the same map                                                               |
| 51  | Every death in the team (bots included) adds `penaltySec` (default 5 s); lives are unlimited; times compare in whole seconds                                                                             | A penalty keeps every team in the race instead of ending runs; bots count so filling with bots is no advantage                        |
| 52  | Run order: game 1 by lot, then the team that ran second starts                                                                                                                                           | Running second (knowing the time to beat) is an advantage, so it alternates                                                           |
| 53  | Not at the exit within the time limit = DNF: an exit always beats a DNF, between DNFs monster points decide, then fewer deaths, then lot                                                                 | A run must always produce a result                                                                                                    |
| 54  | Monster Hunt lives in its own server-side package `UTTourneyMH_v1` (`TournamentMH extends MonsterHunt`, logic in `TourneyCore`)                                                                          | Servers without Monster Hunt keep loading `UTTourney_v1`; the tournament logic exists once                                            |
| 55  | Organizer results are `match.result` events with `outcome: "override"`; correcting a played match voids later results whose pairing changes (the engine's stale results) and they are played again       | One mechanism for walkovers, decisions during a game and corrections; the log stays the single source of truth                        |
| 56  | "Restart" replays only the current game (Monster Hunt: run) on the same map and is not logged                                                                                                            | The usual fix for a technical problem; earlier games of a series stay valid                                                           |
| 57  | Discord notifications are sent by the website (webhook for the channel, bot for direct messages), both optional; failures are logged and never block anything                                            | The website knows users and the event log; the tournament must run the same without Discord set up                                    |
| 58  | Channel per tournament: default webhook, own webhook or off; direct messages on by default, players switch them off in their profile                                                                     | One community channel by default, special events can post elsewhere; nobody gets DMs they do not want                                 |
| 59  | Releases are one platform-independent bundle (bundled JavaScript + npm lockfiles; `npm ci --omit=dev` on the target) with install scripts for Linux/Raspberry Pi (systemd) and Windows (scheduled tasks) | Native modules get the right binary for the target CPU; a Pi 3 never has to build the web app                                         |
| 60  | The mod is built with `ucc` on the game server by the install script; clients download it from there                                                                                                     | One build per server, no binary in the repository; players never need a matching local copy                                           |
| 61  | An organizer can end a Monster Hunt run; it counts as not finished with the progress so far                                                                                                              | Stuck bots must not block a match; the other team still gets its run, and setting the whole match result would be too much            |
